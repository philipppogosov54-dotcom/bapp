# 🔍 Универсальный промпт для Data Flow & Business Logic Audit

## Как использовать

Скопируй этот промпт и вставь в чат с AI (Cursor, ChatGPT, Claude) после любых изменений в проекте.

---

## 📋 ПРОМПТ ДЛЯ ПОЛНОГО АУДИТА

```
Проведи ПОЛНЫЙ АУДИТ DATA FLOW & BUSINESS LOGIC для проекта.

## Что проверить:

### 1. REQUIREMENTS TRACEABILITY (Отслеживаемость требований)
Возьми PRD (файл PRD_BEAUTYSCORE_V2_FINAL.md) и проверь:
- Каждое требование из PRD реализовано в коде?
- UI отображает то что написано в PRD?
- Бизнес-правила соблюдаются?

Формат ответа:
| Требование PRD | Файл/код | Реализовано? | Комментарий |
|----------------|----------|--------------|-------------|

### 2. DATA FLOW MATRIX (Матрица потоков данных)
Для КАЖДОГО user flow проверь цепочку:

User Action → API Request → Database Write → API Response → UI Update

Найди разрывы в цепочке:
- UI вызывает API?
- API сохраняет в БД?
- Ответ API соответствует данным в БД?
- UI обновляется после ответа?

### 3. STATE CONSISTENCY (Согласованность состояния)
Проверь что одни и те же данные везде одинаковые:
- Что в Database?
- Что возвращает API?
- Что показывает UI?

### 4. CLICKABILITY AUDIT (Аудит кликабельности)
Найди ВСЕ элементы с cursor:pointer и проверь:
- Это <Link> или <button>?
- Есть onClick или href?
- Работает ли переход/действие?

### 5. BUSINESS LOGIC VALIDATION (Валидация бизнес-логики)
Для каждого правила проверь:
- Правило реализовано на backend (не только frontend)?
- Edge cases обработаны?
- Ошибки показываются пользователю?

## Формат отчёта:

### 🔴 КРИТИЧЕСКИЕ БАГИ (блокируют работу)
1. [Описание] - [Файл:строка] - [Как исправить]

### 🟡 ВАЖНЫЕ ПРОБЛЕМЫ (нужно исправить)
1. [Описание] - [Файл:строка] - [Как исправить]

### 🟢 РЕКОМЕНДАЦИИ (можно улучшить)
1. [Описание] - [Как улучшить]

### ✅ ПРОВЕРЕНО И РАБОТАЕТ
1. [Flow/функция] - OK
```

## 📋 ПРОМПТ ДЛЯ БЫСТРОЙ ПРОВЕРКИ КОНКРЕТНОГО FLOW

```
Проверь DATA FLOW для: [название flow, например "Survey completion"]

1. Какое USER ACTION запускает flow?
2. Какой API ENDPOINT вызывается?
3. Какие TABLES и FIELDS обновляются в БД?
4. Что ВОЗВРАЩАЕТ API?
5. Как UI ОТОБРАЖАЕТ результат?

Найди несоответствия между:
- Что ДОЛЖНО происходить по PRD
- Что РЕАЛЬНО происходит в коде

Если нашёл баг - укажи файл и строку.
```

---

## 📋 ПРОМПТ ДЛЯ АУДИТА ПОСЛЕ ИЗМЕНЕНИЙ

```
Я изменил [описание изменений].

Проверь что изменения не сломали:

1. Связанные flows - работают?
2. Данные сохраняются в БД правильно?
3. UI отображает актуальные данные?
4. Нет regression (старое не сломалось)?

Если что-то сломалось - укажи что и как исправить.
```

---

## 📋 ПРОМПТ ДЛЯ PRE-RELEASE CHECKLIST

```
Проведи PRE-RELEASE AUDIT:

1. ВСЕ user flows работают end-to-end?
2. ВСЕ данные сохраняются в БД?
3. ВСЕ кнопки/ссылки кликабельны и работают?
4. ВСЕ ошибки обрабатываются и показываются?
5. ВСЕ требования PRD реализованы?

Формат:
✅ [Flow] - OK
❌ [Flow] - [Проблема] - [Как исправить]
```

---

## 🏷️ Терминология

| Термин | Что это |
|--------|---------|
| **Data Flow** | Путь данных: UI → API → DB → API → UI |
| **Business Logic** | Правила бизнеса (опросы, сроки, лимиты) |
| **State Consistency** | Данные везде одинаковые |
| **Requirements Traceability** | Связь требований с кодом |
| **Acceptance Criteria** | Критерии приёмки (что считается "готово") |
| **Regression** | Поломка старого при добавлении нового |
| **Edge Case** | Нестандартный сценарий |
